# MaidsoulKitchen 1.21.1 beta 0.1.4 upstream sync

This note records the provenance and reconciliation boundary for the 1.21.1 fork. It exists because the official GitHub `1.21.1` branch had not published the 0.1.4 source commit when this sync was performed; the authoritative 0.1.4 source artifact was published on Modrinth.

- Published: 2026-03-13

The source archive was imported without its generated JAR manifest on branch `vendor/official-0.1.4` as commit `a22b503a`. It was merged into `sync/official-0.1.4` as commit `8e4f9655` rather than flattened, so future upstream comparisons retain a clear merge boundary.

## Fork changes retained during reconciliation

- Native dual-coordinate cooking state and one-shot reachable side-position search (`a2d4d2e`).
- Native DrinkBeer inventory, cup, barrel-return, and dirty-state safeguards (`c7746b7`, `b33d2db`).
- Restored altar compatibility data (`b33d2db`).
- Native Kaleidoscope Cookery steamer task, recipe filter, and Culinary Hub storage integration (`a85740c`).

The temporary Public patch coordinate Mixins were not imported because the native dual-coordinate implementation supersedes them.

## Local reconciliation after the merge

- Registered the native KC steamer task with the 0.1.4 class/API compatibility checker and pinned its supported range to `[1.4.1,2)`.
- Made compatibility metadata generation tolerate optional API classes that are absent from the data-generation runtime.
- Restored the TLM maid-container client Mixin entry present in source but missing from the official compatibility Mixin list.
- Kept `damages_burn.json` as one main resource and removed its duplicate generated copy.
- Removed obsolete generated altar duplicates; the maintained altar recipes live under the MSK namespace in main resources.
- Routed work-task access to `EntityMaid#getAvailableBackpackInv()` through one cached reflective adapter. TLM 1.1.13 declares `RangedWrapper` as the return type while TLM 1.5.3 declares `CombinedInvWrapper`; direct calls compiled against either descriptor fail on the other runtime.

## Later TLM 1.5.3 baseline migration

The compatibility state above describes the original 0.1.4 reconciliation and is retained as
historical evidence. It was superseded on `brewery/1.21.1-slim` by commit `4554e99f`:

- the compile dependency and minimum runtime range are now TLM 1.5.3 / `[1.5.3,)`;
- the 1.1.13 reflective inventory bridge and legacy slot/pathfinding branches were removed;
- the steamer approach search directly uses TLM 1.5.3 `MaidPathFindingBFS`;
- Farmer's Delight mushroom colonies are registered through the official
  `ILittleMaid.registerSpecialCropHandler(SpecialCropManager)` callback;
- the crop behavior is adapted from MaidSoul Brewery Public commits `f5e0fa9` and `de47e15`.

The migration passed 44 tests and `clean test build`. A NeoForge 21.1.244 development server
loaded TLM `1.5.3-neoforge+mc1.21.1`, logged successful special-crop registration, and reached
`Done (5.606s)`. Gameplay validation of planting and both harvest paths remains separate.
