# MSK 1.20.1 functional forward-port

This note records the intentionally selected functional changes taken from the
official MaidsoulKitchen `1.20.1-1.0-dev` branch and adapted to NeoForge 1.21.1.
It does not import MaidSoul Brewery features into the upstream-only branch and
does not reintroduce the official 0.1.4 compatibility-analysis framework into
the slim branch.

## Source and branch boundaries

- Official source reference: `Wall-ev/MaidsoulKitchen`, branch
  `1.20.1-1.0-dev`, audited at commit `58ec08ec`.
- Upstream-only forward-port: `DemSum/MaidsoulKitchen`, existing branch
  `1.21.1`, commits `afee9d95` and `5dece088`.
- Product adaptation: local branch `1.21.1neo`, retaining the fork's
  native reachable-side search, work locks, steamer integration and inventory
  safety fixes.

## Cooking target behavior

- The real cooker coordinate remains distinct from the maid's standing point.
- `WORK_POS`, `TARGET_POS`, `DESTROY_POS` and `LOOK_TARGET` identify the cooker;
  `WALK_TARGET` and the cached `COOK_WALK_POS` identify the reachable approach.
- The slim branch keeps its one-shot reachable-side BFS instead of regressing to
  the official facing-only fallback for cookers without a facing property.
- Active cooking tasks now use the official task-level
  `enableLookAndRandomWalk` contract. The remaining TLM Mixin only clears stale
  coordinate state after a task switch; it no longer cancels random-walk task
  selection.

## Culinary Hub behavior

- The UI exposes two binding modes: input and output.
- Existing 0.1.x internal sections remain serialized for item-data
  compatibility and are combined into six logical input rows; output remains
  one row.
- Old input/addition binding keys are read as one deduplicated input binding, so
  existing Hub items remain usable after the UI simplification.
- Any loaded block exposing a NeoForge item-handler capability can be bound.
  Registered chest types retain the existing closed-chest safety check in the
  native steamer storage path.
- Bound storage uses the official 2.5x restriction-radius work range.
- The official crosshair binding hints, updated texture, null-safe inventory
  synchronization and Shift-click persistence fix are retained.

## Deliberate exclusions

- No official 0.1.4 analyzer/generator source was added by this port.
- No Public patch coordinate Mixin was copied.
- No version or tag was changed.
- No CurseForge instance or installed JAR was modified.

## Verification

- Unit tests cover the stable two-mode layout and legacy input-section grouping.
- The existing coordinate geometry, target-state, DrinkBeer, steamer resource,
  inventory binary-compatibility and compatibility-registry tests remain part
  of the clean build gate.
- The clean build passed with 33 tests, and the NeoForge development server
  reached `Done (5.372s)` with the full configured compatibility set.
- Client interaction and full in-game cooking scenarios remain manual release
  gates.
