# MSK 官方功能前移专用区（禁止混入 MSB）

> 本目录记录 `1.21.1` 分支的唯一用途：把 MaidsoulKitchen 官方
> `1.20.1-1.0-dev` 中已经出现的功能，按 NeoForge 1.21.1 API 逐项前移。
> 这里不是 MaidSoul Brewery（MSB）功能分支。

## 来源边界

- 目标基线：`origin/1.21.1`，审查起点 `6faa84a1`（官方 0.1.3）。
- 功能参考：`upstream/1.20.1-1.0-dev`，审查点 `58ec08ec`。
- 隔离工作树：`MSK_ORIGINAL_PORT_1.21.1_ONLY`。
- 允许来源：MSK 官方仓库代码、资源和提交行为；为适配 Minecraft/NeoForge
  1.21.1 所需的最小 API 改写。
- 禁止来源：`brewery/1.21.1-slim`、Maidsoul-Brewery-Public 的 mixin、
  DrinkBeer/MSB 私有修复、MSB 的 BFS 侧面寻路、MSB 版本号和 MSB 资源。
- 不把 1.20.1 的 Forge 构建框架、多模块生成器或调试脚手架整包复制到本分支。
- 不移动 tag，不在功能稳定前修改 0.1.3 版本号。

## 已确认并前移

### 烹饪工作点模型

参考官方提交：`a2d35c43`、`90585de2`、`9b333bbd`。

- 新增 MSK 自有 `WORK_POS`。
- `WALK_TARGET` 保存走路点；`LOOK_TARGET`、`TARGET_POS`、`WORK_POS` 和
  `DESTROY_POS` 保存真实厨具点。
- 制作逻辑只从 `WORK_POS` 取得方块实体。
- 女仆离厨具较远但仍有 `WALK_TARGET` 时只等待移动，不清理工作点。
- 长时间制作任务丢失 `WALK_TARGET` 后，由独立路径任务按官方逻辑恢复；厨具无效时清理全部工作记忆。
- 烹饪工作期间通过任务 API 禁止随机游走。
- 删除了官方后续版已经删除的 `MaidRunOneMixin` 广域拦截。

本分支刻意保留官方 1.20.1 的 `getWalkPos()` 行为：有水平朝向时使用朝向侧的
落脚点，无水平朝向时回退到厨具自身。没有引入 MSB 的 BFS。因此“无朝向厨具仍可能
选择自身方块”是当前官方算法限制，不应在本分支用 MSB 逻辑悄悄修正。

### 烹饪中枢简化与交互

参考官方提交：`6e0215d2`、`dfe68e07`、`65ab2696`。

- 配置界面只显示“输入”和“输出”两类绑定。
- 旧五分区 NBT/数据组件继续保存和读取，旧物品不会因界面简化而丢失内部物品。
- 四个旧输入分区被聚合为一个逻辑输入库存，界面显示连续六行输入和一行输出。
- 使用官方更新后的容器贴图。
- Shift 点击中枢槽位后统一写回数据组件，覆盖官方 `21695069` 所描述的容器操作修复意图。
- 任意提供 NeoForge `ITEM_HANDLER` 能力的方块均可绑定，不再限于 TLM 箱子类型。
- 中枢交互距离使用官方后期 `2.5 ×` 女仆工作半径。
- 增加准星位置的可绑定/已绑定/当前模式提示 overlay。
- 修复 1.21.1 数据组件写入时未复制和“清除绑定未写回物品”的问题。

### 同批官方修复

- `MaidRecipesManager` 的库存同步改为 null-safe，并尊重任务的 `enableHub()`。
- Cuisine Delight 炒锅产物进入中枢输出库存，而不是始终进入女仆库存。
- 烹饪任务有 `WORK_POS` 时禁用随机游走。
- 燃烧保护 damage-type tag 在 1.21.1 基线中已是正确的
  `maidsoulkitchen` 命名空间，无需重复修改。

### 构建基线适配

- 目标分支原先引用不存在的 1.21.1 `do-api` Modrinth 坐标，且源码没有使用该 API。
  该可选依赖留空后才能建立可重复编译基线；这不是 MSB 功能移植。

## 验证记录

- Java：本地 JDK 21。
- `gradlew clean build`：通过；当前工程没有独立测试源码（`test NO-SOURCE`）。
- `gradlew runServer`：最终状态下 NeoForge 开发服务端加载至 `Done (4.256s)`，随后已停止测试进程。
- JSON：`zh_cn.json`、`en_us.json`、mixin 配置可解析。
- 中枢新贴图 SHA-256：
  `E4764878EC11AF8D57FAB1885DB2257167BC9B6D381073B9AFA3D77F9D9F7F43`，
  与官方 1.20.1 参考树一致。

仍需游戏内验证：有/无朝向厨具、长时间 Tick 厨具、路径中断、厨具被破坏、
女仆重载、多女仆、中枢旧物品迁移、七行库存点击/Shift 点击、通用物品能力方块、
绑定范围边界、炒锅产物转移。

## 后续提交纪律

1. 每个功能阶段单独提交，提交信息注明官方来源提交。
2. 任何来自 MSB/Public patch 的实现必须拒绝或转到 MSB 分支。
3. 每阶段至少通过 `clean build`；客户端 UI 变更还需开发客户端验证，AI 变更还需开发服务端启动。
4. 推送前再次确认目标远端和分支；不得推送 private backup 的 `main`。
