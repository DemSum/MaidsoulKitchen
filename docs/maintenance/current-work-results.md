# MaidsoulKitchen 1.21.1 slim 当前工作成果

## 1. 文档用途

本文记录 `DemSum/MaidsoulKitchen` 的 `1.21.1neo` 分支当前已经完成的
上游同步、原生功能移植、兼容修复和瘦身成果。它作为后续更新 README、编写提交
说明、发布说明和继续移植功能时的事实基线。

本文只记录已经进入当前分支的内容。计划项、候选实现和仍需游戏内验证的功能会被
明确标记，不能在 README 或发布说明中写成已经验证完成。

记录检查点：`742353b6`（`Anchor tall steamer navigation to its heat source`）。

## 3. 已完成成果

### 3.1 官方 0.1.4 基线同步

- 导入并保留官方 1.21.1 beta 0.1.4 的源码基线和来源记录。
- 保留官方 Farmer's Delight 煎锅、祭坛迁移、客户端兼容修复和服务端启动修复。
- 修复官方源码快照与生成资源之间的重复祭坛配方和伤害类型标签。
- 项目版本保持为 `1.21.1-beta-v0.1.4`，未移动现有 tag。

### 3.2 通用烹饪双坐标架构

- 真实设备位置与女仆落脚位置已经分离。
- `WORK_POS`、`TARGET_POS`、`DESTROY_POS` 和 `LOOK_TARGET` 指向真实厨具。
- `WALK_TARGET` 和缓存的 `COOK_WALK_POS` 指向实际可达落脚点。
- 制作、容器访问和物品交互始终使用真实设备坐标。
- 移动途中只要 `WALK_TARGET` 仍有效就等待移动，不因两类坐标不同而清除任务。
- 设备消失、目标失效、寻路中断或任务切换时仍会清理坐标状态。
- Tick 型厨具保留补充移动目标任务。
- Public 的两个临时坐标 Mixin 没有进入正式 fork；其行为已由原生状态模型取代。

### 3.3 一次性可达侧面搜索

- 保留 Public 修复所证明有效的“从可达落脚点反查相邻厨具”思路。
- 使用一次有界 BFS 搜索实际可达的站立节点，而不是把厨具方块本身作为默认
  `WALK_TARGET`。
- 无朝向属性的厨具不会自动回退到设备自身坐标。
- 搜索结果在任务周期内复用，不进行每 tick 完整 BFS。

### 3.4 官方 1.20.1 烹饪任务约定

- 将 `enableLookAndRandomWalk` 任务级约定适配到 1.21.1。
- TLM Mixin 只负责在任务切换后清除陈旧坐标，不再整体取消随机移动任务选择。
- 保留 slim 已有的双坐标、可达侧面 BFS 和工作锁，不回退到官方仅依赖朝向的
  落脚点算法。

### 3.5 烹饪中枢简化

- 界面收敛为输入和输出两种绑定模式。
- 旧版 input/addition 内部区段继续读取并合并为六行逻辑输入区，旧中枢物品保持
  数据兼容。
- 输出区保持一行。
- 支持绑定加载区块中提供 NeoForge item-handler capability 的容器。
- 注册箱型继续执行关闭箱体安全检查。
- 绑定仓库使用官方 2.5 倍女仆限制范围。
- 保留准星绑定提示、更新后的 GUI 贴图、空引用安全同步和 Shift-click 持久化修复。
- 女仆背包与 TLM 饰品栏中的烹饪中枢均可作为任务输入来源；饰品栏查询先复用
  TLM 1.5.3 的 `BaubleItemHandler.containsItem()` 缓存，确认存在后才定位具体槽位。

### 3.6 DrinkBeer 1.4.1 原生适配

- 移植 Public 提交 `ca84cf4`、`0a0a46b` 和 `f5e0fa9` 中与酒桶任务有关的行为。
- 修正啤酒桶输入材料、空酒杯补充、返还桶回收和成品取出。
- 每次修改酒桶库存后调用 DrinkBeer 1.4.1 的公开更新接口，保证状态持久化和同步。
- 使用 DrinkBeer 1.4.1 的公开状态 API，删除访问私有字段的 Mixin 和 Accessor。
- 恢复 DrinkBeer 杯装啤酒配方以及水、牛奶、小麦输入标签。

### 3.7 祭坛资源

- 恢复烧伤保护饰品祭坛配方。
- 恢复烹饪中枢祭坛配方。
- 保留清晰的 Public 来源记录和 credits。

### 3.8 Kaleidoscope Cookery 蒸笼

- 增加 MSK 原生蒸笼任务、任务数据、配方过滤界面和网络同步。
- 完成从中枢输入仓取材、放入材料、等待蒸熟、取出成品、写入指定输出仓的链路。
- 使用真实蒸笼坐标交互，并从一次 BFS 找到的侧面落脚点接近设备。
- 使用工作锁避免多名女仆同时认领同一蒸笼层。
- 支持半蒸笼和整蒸笼的不同槽位数量，以及仅顶部封盖的连续蒸笼结构。
- 按 KC 1.4.1 的 `SteamerBlockEntity.MAX_LIT_LEVEL` 识别最多四层连续蒸笼的
  向上传热。
- 搜索高度和交互距离已经覆盖第四层；第五层超出 KC 原生热传播上限。
- 修复蒸笼配置包在“配置候选任务”阶段被服务端静默丢弃的问题；现在拥有女仆的
  玩家可在任务选择界面保存黑白名单，服务端仍会过滤未知配方 ID。
- 蒸笼配方悬浮提示现在明确显示当前黑/白名单模式和该配方是否允许烹饪；高级
  物品提示开启时同时显示配方 ID。
- 蒸笼过滤界面的任务按钮、模式按钮、搜索按钮与输入框、7×4 配方按钮网格和
  滚动条使用与 Farmer's Delight 厨锅 `CookConfigGui` 相同的坐标和尺寸。

单层完整链路已经由维护者在游戏内确认。多层代码、单元测试、构建和开发服务器
验证已经完成，但 2/3/4 层组合仍需游戏内确认。

### 3.9 任务注册与兼容修复

- 修复 Farmer's Delight 厨锅等任务的兼容清单映射，避免已实现任务不出现在 UI。
- 当前统一注册和保护 19 个活动任务。
- 修复浆果任务仍覆写 TLM 已废弃的两参数可达性接口的问题；现在直接覆写 TLM 1.5.3
  的共享 BFS 接口，并在目标同层九宫格内接受任一可达落脚点。
- 浆果可达性检查复用 TLM 当前搜索建立的 `MaidPathFindingBFS`，不会为每个候选作物
  重新创建完整寻路搜索。实现原生适配自 Public `de47e15`，未移植其 Mixin。
- 将官方庞大的构建期/运行期通用分析框架替换为静态 `CompatibilityRegistry`。
- 任务注册、Mixin gate、API 检查和客户端兼容报告使用同一份静态清单。
- 可选模组缺失或 API 不满足时采用受控加载，不让对应兼容类破坏服务器启动。
- TLM 运行基线已统一为 1.5.3，女仆背包、槽位渲染和寻路直接使用新版公开 API，
  不再保留 1.1.13 反射兼容分支。

### 3.10 TLM 1.5.3 API 与蘑菇群落

- 1.21.1 slim 的编译依赖和模组元数据最低运行版本均提升到 TLM 1.5.3。
- `MaidPlugin` 通过官方
  `ILittleMaid.registerSpecialCropHandler(SpecialCropManager)` 回调注册扩展。
- 原生加入 Farmer's Delight 红/棕蘑菇群落的播种、成熟检测和收获处理。
- 使用刀具收获时保留群落并重置年龄；无刀收获时退回普通蘑菇方块。
- 背包已满时，未能收入女仆物品栏的产物会掉落在作物位置。
- 实现改编自 MaidSoul Brewery Public 的 `f5e0fa9` 与 `de47e15`，README 和源码
  均保留来源说明。
- 蒸笼侧面搜索改为直接调用 TLM 1.5.3 `MaidPathFindingBFS`，仍只在寻找目标时执行
  一次，不引入每 tick BFS。

### 3.11 专项瘦身

- 删除不可编译、不可达、空实现或已经禁用的源码残留。
- 删除无使用方的运行时工具依赖。

### 3.12 TLM 1.5.3 通用烹饪链集中修复

- 通用厨锅、DrinkBeer 酒桶和其他兼容任务统一由 TLM 1.5.3 官方
  `MaidPathFindingBFS` 提供可达节点，不再维护独立 `NodeEvaluator` 遍历层。
- `CookTargetMemory`、`CookWorkClaimTable` 和任务 UID 共同维护目标归属；任务切换、
  目标失效或女仆卸载时释放坐标和工作锁，避免不同烹饪任务串用同一工作方块。
- 设备候选按任务周期轮换，并跳过已被其他女仆认领的方块，修复并排摆放多个厨锅或
  酒桶时反复只处理同一个设备的问题。
- 统一配方输入视图覆盖女仆背包和烹饪中枢输入库存；执行阶段从计划对应的真实来源
  提取材料，不再出现“用中枢库存生成计划、却只从女仆背包取材”的分裂行为。
- Farmer's Delight 厨锅、Cuisine、煎锅和妖怪归乡等现有任务复用同一输入访问约定，
  同时保留各模组自身的容器槽位、配方和交互逻辑。
- 配方、过滤配置或中枢输入变化时统一使旧计划失效；旧任务事务增加模拟插入、失败
  回滚和空物品保护，降低熔炉、砧板、发酵罐等流程中的物品丢失风险。
- 落脚点搜索兼容一格高台面厨具；女仆与工作区存在楼层差且视线确有方块阻隔时，
  会重新建立烹饪移动目标，同层或无遮挡场景不因此取消正常的小范围活动。
- 高蒸笼以整组蒸笼下方的热源方块作为垂直导航锚点，同时仍以真实蒸笼层作为交互
  坐标，避免封盖位于楼板附近时把上层地面误判为落脚楼层。
- 新增任务周期、工作锁、配方失效、数据校验、可达设备搜索和 TLM API 迁移覆盖；
  为定位实机问题加入的临时动作日志已经完整回退，没有保留运行时诊断层。

## 4. 当前 TLM API 状态

- **编译 API 基线：TLM 1.5.3。** 1.21.1 配置使用官方 Modrinth 1.5.3 构件，
  `touhou_little_maid_version=1.5.3`。
- **最低运行版本：TLM 1.5.3。** NeoForge 与兼容 Forge 元数据均声明 `[1.5.3,)`。
- **旧版兼容策略：不再兼容 1.1.13。** 已删除背包返回类型反射桥、旧槽位编号分支和
  自维护的旧版寻路遍历；这些位置现在直接针对 1.5.3 API 编译。
- **新 API 已实际使用。** 蘑菇群落通过 `registerSpecialCropHandler` 注册，蒸笼使用
  `MaidPathFindingBFS`，中枢和蒸笼仓储直接调用新版女仆物品栏接口。

这次迁移只提升依赖/API 基线，没有更改项目版本号、移动 tag 或修改 CurseForge 实例。

## 7. README 可复用摘要

MaidsoulKitchen 1.21.1 slim 以官方 beta 0.1.4 为基线，原生分离女仆落脚位置与厨具
工作位置，并通过一次性可达侧面搜索避免女仆站上厨具。该分支同步了官方 1.20.1
的烹饪任务约定和简化烹饪中枢，原生适配 DrinkBeer 1.4.1，并加入支持配方过滤、
中枢取材与成品回仓的 Kaleidoscope Cookery 蒸笼任务。当前编译和最低运行基线为
TLM 1.5.3，并通过其官方 special-crop API 原生支持 Farmer's Delight 蘑菇群落。
兼容检查器已收敛为轻量静态注册表，同时保留现有任务 UID、旧中枢数据和可选模组
安全加载行为。
