# 1.20.1 功能同步修复计划

## 基线与边界

- 工作分支：`1.21.1neo`
- 起始提交：`6bb4045e0b247eec013f972ca29c81a12360349f`
- 目标运行基线：Minecraft 1.21.1、NeoForge、Touhou Little Maid 1.5.3
- 架构来源：MaidsoulKitchen `1.20.1-1.0-dev` 的工作坐标设计
- 保留 1.21.1 已完成的蒸笼多层候选搜索和 TLM 1.5.3 特殊作物 API
- 不引入 Public patch 的两个临时坐标 Mixin，不引入 SimplePathfinder 源码
- 不修改版本号、tag、CurseForge 实例 JAR、README、changelog 或现有成果说明

## P0：固定复现与诊断

- 保留当前回退基线，不混入工作期游荡限制。
- 增加仅由开发系统属性启用的低频烹饪链诊断。
- 诊断搜索启动、可达节点、候选设备、可操作设备、认领失败和清理原因。
- 正常运行时不得输出日志或执行额外世界扫描。

## P1：统一 TLM 1.5.3 官方 BFS

- 删除通用任务自行维护的 `NodeEvaluator` BFS 生命周期。
- 建立单一薄适配层，统一创建和关闭 TLM `MaidPathFindingBFS`。
- 通用厨具保留可达侧面落脚点，蒸笼保留多层候选映射。
- 每轮搜索只初始化一次配方管理器并只执行一次 BFS。
- 烹饪扫描不再被普通日程/游荡 `WALK_TARGET` 永久阻塞；仅在找到工作后覆盖它。
- 保留 120--239 tick 搜索冷却，禁止每 tick BFS 和逐设备完整寻路。

## P2：统一工作状态、任务归属和设备认领

- 新增烹饪任务 UID 记忆。
- 设备相关坐标固定指向真实方块，移动相关坐标固定指向落脚点。
- 制作、补路和清理均校验当前任务 UID。
- 通用任务与蒸笼共用设备认领，工作期间续期。
- 任务切换、目标失效、女仆离开世界和服务器停止时释放认领。
- 同一 BFS 内进行候选轮换；多个女仆和密集设备不得全部争抢第一个目标。

## P3：配方计划和烹饪中枢一致性

- 配方计划保留 `RecipeHolder` 身份并检测任务配置和配方重载变化。
- 库存快照比较物品 data components 和数量。
- 通用配置网络包校验模式、任务数据键、配方 ID、重复项和数量上限。
- UI 配置变化使当前配方计划失效，不通过高频刷新整只女仆 Brain 实现。
- 通用任务和蒸笼共用覆盖旧四个输入区段的 logical input handler。
- 绑定库存只在烹饪扫描周期内生成有限摘要，不进行每 tick 全箱扫描。

## P4：恢复原 MSK 任务并修复无损事务

- FD 砧板能够接管已经放置的可切割材料。
- 熔炉按实际炉型 recipe type 过滤输入，并通过统一中枢库存工作。
- 输出和容器转移先模拟容量，执行后处理 remainder；回源失败才生成掉落物。
- 分别修复熔炉、Cuisine、茶壶、发酵桶和浆果工具的已确认高风险路径。
- BBQ 盆任务按第三方配方的一次性交互语义只组装一次，输出不可接收时不得消耗状态。
- API v2 和旧任务数据键保持兼容，不删除、不接管新运行状态。

## P5：验证和交付

- 增加纯状态、官方 BFS 生命周期、任务切换、锁、配置失效、中枢视图和无损转移测试。
- 运行 `clean test build` 和 NeoForge 开发服务器启动测试。
- 生成测试 JAR，但不复制到 `1.21.1tests` 或 `0828Maid`。
- 游戏内测试覆盖普通/高/无朝向厨具、楼层、阻挡、16 个酒桶、多女仆、任务切换、
  重载、绑定箱、满库存、长时间 Tick 型厨具。
- 实机验证前不更新版本号、不移动 tag、不删除 Public 临时补丁源码。
